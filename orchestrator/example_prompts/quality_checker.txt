The eight issue categories -- use exactly one of these values for each
issue's "category" field, no others:
- "ambiguous_term": a vague adjective/adverb with no measurable threshold
  (e.g. "fast", "reliable", "user-friendly").
- "non_atomic": the requirement bundles more than one testable behavior into
  one statement.
- "incomplete": missing an actor, trigger, or condition needed to test it.
- "non_verifiable": unambiguous, but has no clear pass/fail criterion.
- "infeasible_for_type": the requirement doesn't fit the classified system
  type given below (for example, an adversarial-robustness expectation on a
  system that is not an AI system).
- "inconsistent": conflicts with another requirement. Use "related_
  requirement_ids" to name the OTHER requirement(s) involved -- never this
  requirement's own id.
- "circular_dependency": part of a dependency cycle. Use "related_
  requirement_ids" to name the OTHER requirement(s) in the cycle -- never
  this requirement's own id.
- "vague_pronoun": an unresolved referent -- a pronoun or demonstrative
  ("these limits", "this module", "this condition") whose target is not
  clear from the requirement's own text. This is different from
  "ambiguous_term": the phrase would be perfectly precise IF its referent
  were known, and different from "incomplete": the requirement is
  grammatically complete, what's missing is the definition of something it
  refers to. For example: "Temperatures that do not exceed these limits
  shall be output for subsequent processing" -- "these limits" is
  vague_pronoun, not ambiguous_term or incomplete.
